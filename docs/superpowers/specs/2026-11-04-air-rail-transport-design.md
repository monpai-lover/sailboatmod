# 固定翼自动运输：航线引导模式

用户在2026-11-04明确选择简化方案：自动运行不必进行真实气动飞行，可以像空中轨道，只需外观看起来正常飞行；并确认这应当解除对飞控学的安装要求。此选择替代旧计划中自动段必须真实配平/升力/舵面起降的要求。

## 行为

沿用玩家装配的Sable机体、注册控制器、真实库存、市场订单和现有机场可视化规划。固定翼自动运输使用同一套航线引导：机位出发、出港滑行、等待跑道、对正、加速起飞、爬升、巡航、进近、接地滑跑、进港滑行、指定机位停稳、交货。地面也跟随规划路径，不再要求飞控学、升降舵、真实起飞性能或轮组校准。

机头方向采用注册控制器的方向；机位末姿态采用机场配置的朝向。路径按弧长推进，拐角平滑，空中具有有界的俯仰和转弯倾斜，地面保持水平。跑道与停机位的直线端点不被平滑器切角。所有速度均为引导模式参数，而非伪造的气动能力证明。

## 边界与架构

1. 新增独立的 `RailAircraftMission`，保存机场/机位/跑道绑定、物理机体标识、阶段、路径弧长和停稳计时。沿用真实市场交货流程，不写原生飞控任务进度，不调用虚拟订单推进。
2. 纯路径模块负责几何、弧长采样和姿态；原生桥只负责独占本机体的受控运动和真实读回。只在服务端推进，暂停、缺区块、路径阻断或机位占用时不推进弧长。不能全维度暂停物理。
3. 现有机场尺寸、地形、所有权、占用和路线绑定校验继续有效；完整机体必须到达分配的机位并真实停稳40个推进中的游戏tick后才交货。货物或收货空间不足时保留原订单和货物。
4. Flight Control 为可选项；没有安装时，固定翼引导流程应当正常启动、运行和交货。安装时，已有外来原生控制权阻止启动，不能和引导控制争抢。
5. 重启保存引导进度，重新绑定同一机体并验证机场修订及实际位置；不按离线时长补飞、不自动重放整条航线。手动接管、取消、控制器移除和失效均有明确的本机体控制权释放/停等行为。

## 验证

先验证路径连续性、地面走廊、起降/停位姿态、有限数据、进度持久化及交货门。再以真实装配机体在隔离服验证完整订单，包括无Flight Control、不同外形、暂停/重启、障碍/占用和重复到达。代码测试、外观和实际账目分别记录；旧实飞失败保留，不计为新模式通过。
