# 網頁地圖物流顯示升級（甲：前端顯示＋軌道運輸準備）

日期：2026-10-28
基線：分支 `tellus-adaptation`
使用者指示：直接實作，不做樣稿與分段確認（「我相信你，不用看了直接做吧」）。

## 範圍

本輪做（子專案甲）：

1. **載具圖示**：帆船、馬車換成精緻的向量圖示，新增列車圖示，隨行進方向旋轉。
2. **軌跡動畫**：
   - 已走段：實線，越接近載具越亮的「彗尾」。
   - 未走段：虛線，虛線朝前進方向流動，並沿線加方向箭頭。
   - 起點、終點各有標記，終點帶脈動。
   - 依運輸方式加特效：帆船船尾波紋、馬車揚塵、列車畫出枕木雙軌並冒煙。
   - 卡住：紅色脈動警示，維持現有的角標。
3. **物流清單**：改成卡片，內容有方式圖示、起訖、進度條、狀態標籤、預計到達、貨物摘要；可依方式（全部／海運／陸運／鐵路）篩選，依預計到達、進度或名稱排序，並能搜尋。
4. **詳情卡**：重新排版，含進度條、數據格、貨物清單，以及「跟隨載具」按鈕，按下後鏡頭會跟著載具移動。
5. **軌道運輸準備（為之後接入 Create 的列車物流）**：
   - 後端新增運輸方式常數 `RAIL`，以及由運輸方式推出的 `vehicleKind`（`sailboat`／`carriage`／`train`），隨物流 JSON 輸出。
   - 前端依 `vehicleKind` 選擇圖示與特效；舊資料沒有這個欄位時，由運輸方式字串推斷。
   - 之後的 Create 整合只要以 `RAIL` 呼叫現有的 `ShippingTraceService.createOrUpdateManualTrace` 即可顯示。

**不在本輪**（子專案乙）：事件時間線、歷史紀錄回看，這兩項需要後端記錄事件與保存歷史。

## 設計

- **新檔案 `marketweb/logistics-render.js`**：
  - 純邏輯部分，可在 Node 測試：運輸方式推斷、依進度切分路徑、箭頭擺放位置、清單篩選與排序。
  - 繪製部分：圖示、軌跡、特效，都畫在 Canvas 上。
  - `map.js` 負責呼叫它，並保留現有的插值、命中測試與動畫迴圈。
- **特效粒子有上限**：每台載具最多 24 個粒子。只在有運輸時才跑動畫，沿用現有的 `shipmentsActive()` 開關。
- **配色**：
  - 方式色：海運青藍、陸運琥珀、鐵路紫。
  - 卡住一律紅色；手動發車沿用暖色光暈。
  - 配合現有亮色與深色主題的 CSS 變數。
- **模擬伺服器**：`tools/marketweb_mock_server.js` 補上 `/api/map/*` 的假資料，三種載具會沿路線移動，供視覺檢查。

## 測試

- **Java**：`TransportModes` 的方式到載具種類對照；物流 JSON 含 `vehicleKind`。
- **Node**：方式推斷（含舊字串 PORT／LAND／SEA…）、路徑切分（進度 0、中段、100%、單點、重複點）、箭頭間距、篩選與排序、搜尋。
- **視覺**：用模擬伺服器加無頭 Chromium 截圖，檢查三種載具、軌跡、清單與詳情。
