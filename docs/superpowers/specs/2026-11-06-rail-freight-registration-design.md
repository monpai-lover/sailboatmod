# Create 列车登记与市场货运

用户已授权补齐列车登记和市场货运，并要求补验航空学船只、车辆。延续 fix_64 已验证的原生列车运行和本镇看板；保留当前工作树的全部既有改动。

## 玩家流程

新增站旁的「铁路货运站」方块。右键打开管理界面，选择附近原生 Create 车站，读取实际停靠列车，核对列车名称、原生唯一编号、所有者及可用货仓，登记为本镇货运列车。原生车站仍负责组装和铁路连接，本方块负责运营登记和市场终端。

登记需要玩家拥有列车并有本镇设施管理权限。站点以原生编号、维度和实际坐标绑定；名称仅用于展示和 Create 原生时刻表的目标匹配。禁止通过改名接管另一车站或列车。一个列车同时只有一个货运登记和一份活动任务。

界面提供站点/列车登记、启用和暂停、当前订单、出发和到达站、货仓及故障说明。未登记列车仍可显示在公共到站看板，不能被市场调度。现有船、陆载具和航空注册器保持各自职责。

## 运输和结算

铁路作为独立终端类型 RAIL，保持在看板的 LAND 类别内。源站和目的站关联实际城镇仓库，市场候选和手动发货入口可选择铁路。复用现有订单预留、运单、托管付款和轨迹数据，不能再次从已上架扣货的源仓重复扣货。

出发前检查原生列车身份/所有者、实际停靠站、铁路连通、控制与时刻表可用、货仓容量，以及目的站绑定。货物只进入实际原生列车存储，持久化保存订单清单及任务，不复制货物。原有人工时刻表不可被静默覆盖；登记操作明确启用货运托管后才能安排货运时刻表。

通过 Create 原生寻路、时刻表和车轮运动前往目的站。只有同一列车在准确目标站停稳、订单货物真实足量、目标仓库具备接收条件时，才进行有幂等检查的入仓与订单交付；沿用已有托管款结算规则。重复 tick、同名站、手动改表、缺货或远处经过都不能触发交付。成功后空车返回源站，再成为可调度状态。

装载或启动失败按本次收据回滚；任务中断保留未交付订单。重启后核对真实列车、货物与已提交交付记录，不按计时器推定完成。列车被拆解、换所有者、登记站被移除或原生任务被人工接管时停止自动调度并显示原因。

## 方案取舍

采用站旁独立方块和原生列车编号绑定，便于关联仓库与管理权限。车载注册方块需要处理 Create contraption 组装迁移，当前不选。仅用命令登记不满足可见管理入口；自动把所有列车纳入市场也缺少运营授权，均不采用。

## 验收

1. 新方块、中文/英文界面、配方、掉落与网络权限完整；无 Create 时核心模组能加载并给出不可用原因。
2. 同名车站与列车不串身份；未授权、重复登记、旧界面重复操作、缺货/满仓不产生错误装货或付款。
3. 实际 Create 列车完成一单：预留货物装车、真实运行、准确停站、目标仓库收到全部货物、订单结算一次、空车返回。
4. 至少一次活动任务重启恢复和一次重复到站验证，货物及付款守恒。
5. 原生列车公共看板行为不回退；既有航空运输不受新增铁路类型影响。

航空学船/车的运行验收另列实施计划，不能用普通 SailboatEntity/CarriageEntity 或飞机滑行结果代替。
