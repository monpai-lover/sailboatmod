# Tellus 適配回交說明（子專案 A：水路自動航線）

日期：2026-10-28
基線：`sailboatmod 1.3.13-fix_5`（交接包 commit `5d2c69bb`）；本地分支 `tellus-adaptation`
規格：`docs/superpowers/specs/2026-10-28-tellus-adaptation-design.md`
計畫：`docs/superpowers/plans/2026-10-28-tellus-water-route.md`
驗證結果（spike）：`docs/superpowers/specs/2026-10-28-tellus-spike-findings.md`

## 1. 做了什麼

在 Tellus 地球世界中：

1. **建立航線不再生成區塊**：區塊有存檔 NBT → 照舊讀真實方塊；沒有 NBT → 用 Tellus 地形預測（原版 `ChunkGenerator.getBaseColumn`，Tellus 已在其中填入真實世界水面）；預測拿不到 → 當陸地。伺服器自動改用單段 NBT 模式，忽略畫面上選的頁籤。
2. **預先下載地形**：兩碼頭直線兩側各 512 格的 Tellus 資料先預取，進度條顯示「下载地形 x/y」；所有等待共用 60 秒預算，逾時區塊當陸地繞開。
3. **航行中前瞻**（只對自動生成的水路航線）：船沿航線往前載入約 160 格的走廊（每船最多 40 個額外區塊），從船的位置起沿航線逐格用真實方塊檢查已載入的部分，長航段也會被部分檢查。遇到障礙就在背景局部繞行（BFS 64 格 → A* 256 格），把繞行段插回航線，船不停；結果未回來時，船在障礙前 48 格內停住等待；繞不開才交給完整自救。船中途重新載入（伺服器重啟等）後守衛會自動恢復。
4. **Tellus 世界的完整自救**：原本的自救用原版噪聲採樣，在 Tellus 世界會把所有地方判成不可航。Tellus 世界改為從船的位置用「NBT＋預測」規劃到目的港泊位，失敗才求救並暫停。
5. **修正回寫**：繞行段寫回船上的航線目錄、來源碼頭的正向航線、目標碼頭的反向航線；碼頭未載入時先存進 `RouteRepairSavedData`，碼頭載入時套用。只改自動生成的水路航線；以內容比對，找不到或出現多次就放棄，不覆蓋。
6. **建立航線畫面**：客戶端裝有 Tellus 時，模式頁籤下方多一行說明。

非 Tellus 世界、或未安裝 Tellus 時：不建立預測器、不建立前瞻守衛、不額外載入區塊，行為與 fix_5 相同。

## 3.1 整體審查

完成後由一位獨立審查者檢查整個分支，找出 1 個嚴重問題與 5 個重要問題，都已修正並各自先寫出失敗的測試：

| 問題 | 修正 |
|---|---|
| 自動航線生成時被抽稀到剛好 256 點，原本 256 點上限讓所有繞行都無法插入，回寫從未發生 | 上限提高到 512；回寫結果超過 512 時放棄 |
| 長航段與船目前所在航段從未被檢查 | 改為從船的位置沿航線逐格檢查已載入部分，障礙以航線上的格子表示 |
| Tellus 世界的完整自救不可能成功（只會暫停求救） | Tellus 世界改用 NBT＋預測規劃到目的港 |
| 船重新載入後守衛消失 | 航行中第一個 tick 自動補建 |
| 預取失敗會讓整片區域被當成陸地且永不重試 | 預取只當提示；失敗的區域下次重新預取 |
| 手動航線（窄運河、橋下）可能被誤判成障礙而暫停 | 守衛只用於自動生成的水路航線 |

延後未修的次要問題：

- 停駛（`stopAutopilot`）恰好發生在背景繞行進行中、且主線程收尾又拋出例外時，共用互斥位可能殘留到船重新載入。
- 前瞻用的地形預測也有 60 秒預算，`getBaseColumn` 自己的下載時間不計入；A* 退路可能預測大量未存檔區塊，占用兩條共用工作執行緒之一，期間船停住等待、玩家建線也會變慢。
- 每 10 tick 重新擷取最多 40 個走廊區塊，即使已檢查過。
- 伺服器重啟後，舊的實體區塊票據不會被回收（原有問題；走廊每船多出最多 40 個）。
- 測試缺口：`RouteRepairService.submit`／`applyPending` 與重新載入流程只有原始碼字串檢查，沒有行為測試。
- 客戶端只要裝有 Tellus 就顯示說明文字，包括普通世界預設（規格如此要求，只是措辭問題）。

## 4. 未驗證項目

- **遊戲內建立航線與航行**沒有在真實客戶端跑過：需要玩家、碼頭與船，本機只有 dedicated server。前瞻、繞行、拼接、回寫的邏輯由單元測試覆蓋（含牆、封死、船已越過起點、結果遲到、例外時釋放互斥位等情況）。
- 超長航線（數千格以上）在真實網路下的下載時間與 60 秒預算是否足夠，未實測。
- 多艘船同時在 Tellus 世界自動航行時的區塊載入負擔，未實測（每船上限 40 個額外區塊）。

## 5. 請在 Windows 遊戲內驗證

1. Tellus 地球世界中，在兩個相距數千格的海岸城鎮建立跨海峽航線：進度條先出現「下载地形 x/y」，完成時間合理，伺服器不卡頓。
2. 航線中途用石頭蓋一道牆，開船：船在到達前繞開並接回原線，不需要擱淺後自救。
3. 再開一趟：走的是修正後的航線，不再偵測同一道牆；目標碼頭的反向航線也已修正。
4. 未安裝 Tellus 的普通世界建立航線：結果與 fix_5 相同；建立航線畫面沒有 Tellus 說明文字。
5. 已安裝 Tellus 但用普通世界預設：行為與 fix_5 相同（畫面上會有說明文字，但伺服器不啟用 Tellus 路徑）。

## 6. 執行時的取捨（計畫外決定）

- 泊位解析沒有接上預測器：它在主線程執行，而 Tellus 下載會阻塞數秒；碼頭所在區塊必定存在，NBT 已足夠。
- 前瞻從船正駛向的那段開始檢查；船與下一個航點之間的障礙仍由既有被動脫困處理。
- 船已越過繞行起點時，改從船的位置重算一次（背景執行），這種繞行依賴當下位置，不寫回。
- 升級為完整自救前先釋放共用互斥位；所有回呼路徑在例外時都會釋放，避免自救永久失效。
- 新增與修改的 `.java` 一律使用 CRLF，與 fix_5 原始碼一致。

# 網頁世界地圖（Tellus）

規格：`docs/superpowers/specs/2026-10-28-tellus-web-worldmap-design.md`

## 做了什麼

Tellus 地球世界的網頁地圖分三層，由下而上：

1. **真實世界底圖（A）**：前端直接載入，可切換來源：ESRI 衛星（預設）、高德街道、OSM、OpenTopoMap。
   - 高德在中國範圍內做 GCJ-02 偏移修正。
   - 右下角標示來源；連續 8 次載入失敗會提示「可切換來源」。
   - 玩家的選擇記在瀏覽器裡。
2. **Tellus 預測層（B）**：伺服器有人看才畫。
   - 每個像素用 Tellus 的預載地形資料取樣一點，配色與高度陰影沿用現有網頁地圖。
   - 每像素 1 格的層級用 Tellus 的 LOD 地表方塊（每 4×4 像素查一次）；每像素 2–16 格的層級依 ESA WorldCover 土地覆蓋分類取代表方塊上色。
   - 專用單執行緒、去重、最新的先畫、佇列上限 256。
   - 瓦片存在 `data/sailboatmod_market_web_map/tellus/`。
3. **現有真實地形瓦片**：未改。未渲染的地方本來就是透明的，所以 B 會從下面露出來。

另外：

- **縮放範圍**：Tellus 世界的最小縮放降到能看整個地球。
- **B 的覆蓋範圍**：只到每像素 16 格（`tellusTileMaxZoom = 4`），更遠只顯示 A。spike 實測每像素 256 格的層級一張瓦片要約 25 分鐘。
- **非 Tellus 世界**：`/api/map/world` 回 `tellus:false`，前端不加任何新圖層，縮放限制照舊，行為與原本相同。

## 需要你確認的改動（與原先約定不同）

1. **B 的配色**：你選的是「Tellus 的 LOD 地表方塊」。實際做法是：
   - 每像素 1 格的層級才用 LOD 地表方塊。
   - 每像素 2–16 格的層級改用 ESA WorldCover 土地覆蓋分類對應代表方塊，仍用 Minecraft 方塊配色。
   - 原因：實測 LOD 地表方塊每次查詢都會下載完整解析度的高程、陸地遮罩與 OSM 水體，冷資料一張遠景瓦片超過 10 分鐘；改用土地覆蓋後約 6–18 秒。
   - 如果你寧可慢也要 LOD 方塊，可以改回來。
2. **B 的覆蓋範圍**：原規格是層級 0–11，實際只到 4（每像素 16 格）。每像素 32 格以上只顯示真實世界底圖。原因：每像素 256 格時一張瓦片約 25 分鐘。

# 浮字（全息名牌）修正

**現象**：fix_5 中，國家核心、城鎮核心、碼頭、驛站、市場、銀行、倉庫、酒館、兵營、民居等功能方塊頭頂的浮字全部消失；帆船、馬車的到站浮字與國家核心搬遷預覽的浮字也受影響。

**原因**：升到 1.21.1 後，`EntityRenderDispatcher.cameraOrientation()` 的定義改了，它與視圖旋轉互為共軭。原版 1.21.1 名牌（`EntityRenderer#renderNameTag`，反編譯確認）是先套用它，再縮放 `(0.025, -0.025, 0.025)`。我們的浮字仍用舊版的 `(-0.025, -0.025, 0.025)`，文字被鏡像到背面，遭背面剔除而看不見。這和 Tellus 無關。

**修正**：新增 `client/renderer/HologramBillboard.faceCamera`，與原版名牌相同的變換，12 處浮字全部改用它。

**測試**：`HologramBillboardTest`。
- 在多種鏡頭朝向下，以真實矩陣運算驗證文字在畫面上由左到右、由上到下，與原版名牌一致。舊的負 X 變換會讓這項測試失敗（已確認先失敗再通過）。
- 另一項測試確保沒有任何繪製器再出現「`cameraOrientation()` 加負 X 縮放」的寫法。

**完整測試**：349 組、1,543 項測試全部通過。遊戲內畫面請在 Windows 上確認。

# 網頁市場物流顯示升級（子專案甲：前端＋軌道運輸準備）

設計說明：`docs/superpowers/specs/2026-10-28-web-logistics-visuals-design.md`。

## 做了什麼

- **載具圖示**：帆船、馬車換成新的向量圖示，並新增列車，會隨行進方向旋轉。三種方式各有顏色：海運青藍、陸運琥珀、鐵路紫。
- **軌跡動畫**：
  - 已走段是實線，越靠近載具越亮。
  - 未走段是虛線，虛線往前流動，沿線有方向箭頭。
  - 起點與終點有標記，終點會脈動。

# 模組強化（2026-10-29）

依「模組改進建議」逐項處理，遊戲內自動測試依指示先不做。每項都先寫會失敗的測試再修正。

## 1. 超長道路（道路規劃器）

**實測結果**：用起伏地形加河流的模擬地形測量，預覽的耗時隨長度平方成長，全部在伺服器主執行緒上跑，確認時還會再算一次。

| 道路長度 | 修正前 | 修正後 |
|---|---|---|
| 2,000 格 | 1.5 秒 | 0.19 秒 |
| 10,000 格 | 29 秒 | 1.0 秒 |
| 20,000 格 | 111 秒 | 3.6 秒 |

修正前約 14,000 格以上的道路會觸發 60 秒看門狗，讓伺服器當機。修正後的結果與修正前逐格相同（方塊數與步驟數一致）。

**找到並修正的問題**：
1. **平方複雜度**：每個路面格都掃描整條中心線找最近線段。改為 16×16 格網索引，結果與逐條掃描完全一致，含自我交叉的道路。測試以逐條掃描結果比對。
2. **主執行緒同步載入區塊**：原本一次同步載入最多 6,000 個區塊，未生成的區塊在主執行緒上生成。改為以區塊票證分批載入（每 tick 48 個，同時最多 192 個等待中），只在區塊真正生成完成後才計算預覽。
   - 載入期間玩家會看到進度。
   - 2 分鐘逾時；取消、登出或伺服器關閉時會釋放區塊。
   - 多位玩家共用的區塊以持有數計算，不會互相卸載。
3. **超過上限時路面被埋進地底**：超過 6,000 區塊的部分原本被當成世界底部，路面直接蓋進地底，而且沒有任何提示。現在會明確拒絕並提示分段規劃（約 3 萬格直線）。
4. **確認時重算**：改為直接使用預覽時算好的步驟，確認時不再載入區塊與重新編譯。
   - 新的預覽請求會立即取消舊預覽。
   - 載入中不能確認。
   - 玩家在載入中換了維度，就不會在錯誤的維度建造。
5. **客戶端預覽只畫前 4,096 個方塊**：長路走遠後就看不到預覽。現在改畫離鏡頭最近的方塊。

**仍待你決定**：
- 施工佇列只存在記憶體，伺服器重啟後未完成的道路會遺失。
- 施工速度是每 tick 8 步，一萬格的道路約需 53 分鐘。
- 持久化與加速都牽涉遊戲節奏，本輪沒有改。

## 5. 網頁市場安全

**找到並修正的問題（都不需登入即可利用）**：
- **國旗路徑穿越**：`/api/map/flags/%2E%2E%2F...png` 可讀取伺服器硬碟上任何 `.png`。
- **`/assets/` 路徑**：沒有擋 `..`。
- **請求本體沒有大小上限**：一個超大 POST 就能耗盡記憶體，讓整個 Minecraft 伺服器當機。現在超過 64 KiB 即拒絕（413）。
- **執行緒沒有上限**：每個連線都開一個新執行緒。現在固定 16 條、最多 256 個排隊，超出的連線直接關閉；另外加上請求與回應的時間上限。
- **登入沒有失敗次數限制**：可無限猜密碼，且每次都耗用大量 CPU。現在：
  - 每個位址、以及每個「帳號＋位址」，15 分鐘內失敗 10 次即暫停（429）。
  - 「查無帳號」與「密碼錯誤」回應相同，耗時也相同。
  - 反向代理後面的伺服器，請在設定 `webTrustedProxies` 填入代理位址，限制才會以真實客戶端計算。
- **回應標頭**：加上 `nosniff`、`X-Frame-Options: DENY`、`no-referrer`。

**仍建議注意**：
- 網頁市場預設綁定 `0.0.0.0` 且是明文 HTTP。對外開放時請放在 HTTPS 反向代理後面。
- `app.js` 有 6,000 多行，跨站腳本（XSS）沒有逐行審過。
