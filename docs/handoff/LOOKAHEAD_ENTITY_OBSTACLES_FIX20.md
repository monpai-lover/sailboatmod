# fix_20：移动生物、前瞻误判与自动航行换挡

移动生物不再作为静态绕行几何；同时修复前瞻检查误判同一航段、重复插入绕路航点，以及远处后台规划触发立即停车的问题。游戏网络协议保持 **22**，模组元数据保持 **1.3.13**，不新增数据包、同步字段或存档字段。

## 日志与原因

报告中的同一段 `(37282,65,-55395) → (37284,65,-55397)` 每隔十 tick 被重新判为障碍，绕行后航点数从 178 增至 190，状态反复在 `SAILING`／`RECOVERING` 之间切换。现有最短换挡保持时间挡不住这个过程，因为后台修复的早期返回直接要求 STOP，并把速度上限设为零。

确认了三类相互独立的问题：

- 局部物理避障把所有可碰撞实体的包围盒冻结在快照里，包括正在移动或暂时站住的生物。现在只采纳固定且可碰撞的装饰实体，以及已知类型中真正停泊、无人乘坐、未自动航行、发动机停止的载具；玩家、生物、掉落物、投射物和活动载具不进入静态规划快照。原版实体碰撞和推动行为保留，不通过删除、传送或穿透实体来解决。
- 日志中的 `[Lookahead]` 使用方块水列，不直接读取生物。它自己的旧走格方法会多检查斜线之外的格子，和真实精寻的精确走格不一致。在受控地形中，使用日志原坐标和一个航道外的陆地方块即可重现假障碍及每轮增加两个航点。现在前瞻和走廊使用与精寻一致的精确边界计算，真实对角触角仍需检查。
- 前瞻与局部自救共用请求互斥位，旧逻辑把所有占用都当作必须立即停车的自救。现在请求区分用途；远处前瞻可以后台执行，近障碍仍由原有 48 格保护范围要求停车，真正的局部自救仍要求立即停车。停止航次、取消与迟到回调的身份校验保留。

绕行接回原航线前，还必须检查新引入的连接几何，拒绝没有改变原受阻边的重复拼接；无法证明安全的结果不写入码头航线。长航段、未知地形和预算耗尽的边界由专项回归覆盖，避免重新形成高频重算与停车循环。

已知近处障碍遇到未知地形时继续保持停车保护，释放后台工作互斥位，至少等待 100 tick 后再尝试；新航次、路线变更或已经完整验证原航段恢复可通时解除旧保护。只跳过与原航段完全共线、同高度且位于原端点之间的保留连接部分，新绕行边仍须严格验证；新增几何超过有限预算时交给已有的有界局部自救，不无限重算。
