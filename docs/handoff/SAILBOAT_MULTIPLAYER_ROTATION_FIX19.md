# fix_19：多人帆船转向同步

修复驾驶者看到的船头方向与乘客／旁观者不一致、停止转弯后仍保持错误朝向，以及跨过整圈时画面突然反转的问题。协议保持 **22**，模组元数据版本保持 **1.3.13**；没有新增数据包、同步字段或存档字段。

## 原因和修改

1. 自定义网络插值先应用驾驶端传来的角度，随后通用转向限制又将远端副本限制为每 tick 0.85°；手动驾驶物理实际可以达到 1.4°。角度被丢弃，但位置和插值计数继续前进，因此会产生累积朝向偏差。现在网络控制的客户端副本直接采用插值角度，并更新交接用的上一帧朝向；本地驾驶和服务器原有转向逻辑保持不变。
2. 帆船重写了 `lerpTo`，但未重写原版五个 `lerpTarget*` 读取方法。位置包和角度包分开发送时，原版网络接收器会读取错误的旧插值状态，覆盖仍未完成的目标。现在这五个方法统一读取帆船自己的待完成目标，插值结束后返回当前位置和角度。
3. 网络转向的 `setRot` 会将角度按 360 取余；渲染原先对前后角度普通插值，`359.8° → 0.2°` 的半帧会错误地朝向 180°。现在渲染使用的 `getViewYRot` 沿最短角度插值，完整帧仍返回精确当前朝向。

原有十 tick 平滑、本地驾驶预测、重船转向惯性、自动航行和座位偏移规则保留。

## 回归验证

先在未修复代码上执行新用例：10 项中 7 项按预期失败。实际生产实体接收方法中，持续正／反向转弯的最大角度误差分别达到约 134.30°／134.85°；单个网络插值产生的 9° 被限制回 0.85°；跨圈半帧渲染得到反向 180°。这些是测试对象上的复现结果，不是从线上玩家录制的数据。

修复后 **70 项相关测试通过**，包括 **11 项新的多人角度回归**：

- 持续双向转弯，使用原版有符号字节量化角度，误差保持在原有平滑范围内；最后一个包之后收敛到精确目标。
- 位置包保留角度／俯仰目标，角度包保留位置目标。
- 正反跨 360° 的半帧显示沿短弧移动。
- 本地驾驶预测、接管驾驶位、服务器转向限制和自动航行保持正确。

用例构造真实 `SailboatEntity`，按生产 tick 顺序调用实际插值和限速方法，并调用渲染器使用的角度 API。测试中的世界和驾驶者仅提供接收路径需要的最小状态，不启动网络连接或渲染窗口；这不等同于两台 Minecraft 客户端的实际联机验收。发布包 `verification/` 记录最终全量测试、正式加载器检查和 JAR 哈希。

最终 `releaseMod -PfixIndex=19` 构建成功，**2664 项全量 Java 测试通过**，无失败、错误或跳过，含官方 Tellus 遮罩回归。独立的 NeoForge 21.1.265／Java 21 平坦测试服务器完成 **33 项检查**：除原有调试网页生产流程外，实际生成帆船、读取唯一标签与 `Rotation: [90.0f, 0.0f]`、只清理指定实体并确认不存在，正常停服且无 ERROR/FATAL 日志。正式服务器测试的输入 JAR 与交付 JAR 哈希一致。

与 fix_18 对比，JAR 条目集合和元数据完全一致，890 个客户端目录、网络、资源及原网络模式条目逐字节相同；变化仅涉及两端共用的 `SailboatEntity` 及其内部类。接收端修复位于这个共用实体类，因此这些目录不变并不意味着旧客户端已获得修复。

## 更新范围

这次修复在接收端生效，**乘客和旁观者的客户端必须换新版主 JAR**。建议服务器和所有玩家统一使用包内的 `sailboatmod-1.3.13-fix_19-neoforge-1.21.1.jar`。仅更新服务器无法修正旧客户端中的限速和插值代码；这点与前面的 fix_18 纯服务器更新不同。

退出客户端并停服，备份移出旧主 JAR，把包内 `mods/` 的主 JAR 分别放入客户端和服务器 `mods`，不要同时保留两份主模组。保留 MarketWeb 附属、GeckoLib、LDLib2、其他依赖及存档。

安装后可用两名玩家复核：A 驾驶，B 先在岸边观察，再作为乘客；持续左右转弯后松舵，并跨过整圈转向、切换驾驶位和自动航行，检查船头是否持续跟随并在停止后归于同一角度。网络延迟及原有平滑仍可能产生短暂跟随差。
