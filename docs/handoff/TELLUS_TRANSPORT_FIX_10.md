## 共享预测／真实地图怎么使用

道路规划器、城镇和国家界面使用同一地图通道。拖动平移、滚轮缩放即可；在 Tellus 世界中，尚未生成的远方先显示预测地形，已加载地形和已保存的完整区块 NBT 逐步提供真实数据，并覆盖对应位置的预测。预测只是规划参考，海岸、河流及后续地物仍可能与真正生成的结果不同。

预测层与真实切片、真实覆盖索引分别存储。看到预测颜色不表示对应世界区块已经生成，也不表示该处满足通行或施工条件。普通打开、拖动和缩放采用视野流式请求，不会为填满整幅地图而强制生成可见世界。远景使用随缩放调整采样间距的切片，先看大范围走势，放大后再看局部细节。

“强制渲染”仍是明确的单独操作。需要核对局部实际地形时再选择合适的小范围；过大的选择会在展开区块清单之前被拒绝。超远视图不会自动转为旧式整片强制渲染请求。

城镇／国家的领地叠层按已知领地绘制；大范围框选显示裁切后的外框，不再逐个绘制所有选中区块。领地权限与提交时的服务端检查继续生效。

## 超长水路

1. 打开起点码头的“航线”页，点击“自动”，在“创建自动航线”窗口选择目标码头，再点击“创建航线”。起终点仍需满足已有的城镇、国家、同国／盟友／贸易关系权限和可用泊位规则。
2. 等待屏幕上方进度条。超长 NBT／Tellus 规划在距离超过 **8,192 格**时进入分层搜索，先显示“全局水域走向”，再显示“分段精寻 n/m”；未知数据尚未就绪时显示“等待地形”。只有完整结果成功后才保存路线，部分进度不表示已经创建出可执行航线。
3. 创建成功后按现有码头、路线书和载具流程选择并执行路线。普通帆船保存完整路线和全局航点进度，运行时只提供有限前瞻窗口；窗口滚动不表示删除远方路线。现有导航暂停／继续／停止继续使用，本次没有增加中途靠站功能。

旧的约 **12,288 格**起点范围不再是这条超长分层路径的总距离硬限制；但全局粗搜仍有 **32,000 节点**预算，局部精寻段长度至多 **4,096 格**，并受搜索时间和真实／预测地形可用性限制。找不到水路、预算耗尽或超时仍可能失败，不能承诺任意两点都能连通。

目前没有新增玩家专用的“取消水路规划”按钮或指令。载具的暂停／停止控制的是导航，关闭创建窗口也不应视为取消后台计算。服务端的取消与停服清理、预测任务中断及路线重启恢复，仍须按最终原生复验结果判断，不能从本节的保存实现推断已完成实际重启或远航验收。

## 超长道路：先预览，再按真实地形施工

1. 打开道路规划器，选择起终点并编辑路径节点。按路段用途选择道路、桥梁等类型；跨水处应明确选择桥梁。长距离压缩的普通道路段遇到实际采样水体会给出提示，不会自动把整段道路铺进水里。
2. 提交预览后等待进度。长路线保留压缩节点，后台逐个处理局部窗口；预览不会先生成整条远方走廊。总览保留有限路线点，附近显示有限幽灵方块，因此远景简化或局部逐步出现是预期行为。
3. 完成预览后，在原维度检查路径、材料和桥梁方案，再确认施工。切换维度后不能确认旧维度的预览；拒绝时不会消耗该预览。
4. 正式施工只预热当前窗口，重新读取真实地形并编译本窗口，再逐步放置。预测步骤不会直接作为可执行施工清单。每个窗口完成后刷新当地几何，释放旧的加载票据，再进入下一窗口。
5. 如果真实岸线、障碍或桥梁净空与预览不兼容，施工会暂停并提示取消／重新预览。先处理提示，不要将预测地图当作已经清障的施工许可。
6. 从施工菜单选择“取消建造并回滚”可撤销已执行部分。回滚也分批处理并预热当前邻近区块；等待回滚结束后再确认自己的新道路。

同一玩家有施工或回滚进行时，新确认会被挡住，新预览仍然保留；其他玩家不受该玩家任务占用影响。对应提示为“请先完成或取消当前道路施工，再确认新方案。当前预览已保留。”或“前一条道路仍在撤销，请稍候再确认。当前预览已保留。”

实现以 **128 格核心段＋两侧 32 格采样余量**处理窗口，施工和回滚各最多执行 **8 条记录／tick**。桥梁保留整段桥面、引桥和桥墩的全局关系；采样余量不会重复执行相邻路段。实际已建历史及撤销记录仍随已执行长度增长，不能将整套道路系统描述为恒定内存。

路线位置使用 BlockPos 的有符号 26 位 X/Z 范围 `[-33,554,432, 33,554,431]`，包含既有 Tellus 坐标 `X=33,431,923`。这表示坐标可以表达，不等于已验证在边界附近完成了实际施工或行驶。

## 两种注册控制器怎么登记

| 用途 | 方块名 | ID |
| --- | --- | --- |
| 船舶运输 | 船舶注册控制器 | `sailboatmod:vessel_registration_controller` |
| 陆地运输 | 陆运注册控制器 | `sailboatmod:land_vehicle_registration_controller` |

两种控制器自身的实际质量均为 **0**，不提供额外推进力。整艘船／整辆车仍须有有限且大于零的总质量，并且具备玩家搭建的真实动力、转向和制动装置。

1. 将合适的控制器放到要登记的船／车结构内，检查其朝向。控制器朝向用来确定载具前向；按真实船首／车头布置。
2. 可以先保存名称和配置；随后用航空学将整套结构物理化。未物理化的普通世界方块不能登记为载具。
3. 由所有者或管理员靠近控制器的实际世界位置，在 **8 格内**空手交互打开面板。面板分为“状态”“货舱”“航行与道路”“动力连接”。“状态”会显示实际位置、尺寸、结构质量、登记标识和当前物理结构。
4. 填写“载具名称”，点击“保存名称”，再点击“登记结构”。一个实际结构只能有一个启用的登记控制器；重复登记或全零总质量结构会失败。
5. 完成下面的货舱、动力、终端和路线配置后，再尝试启航／发车。仅登记成功不会代替动力配置。

登记标识与当前物理结构标识分别保存，重新组装不以新的物理结构 UUID 充当新的物流身份。结构卸载、拆分或移除时仍会重新检查有效性；请在面板刷新状态，不要把暂时未加载当成已经到港。

## 只让选中的真实容器参加物流

在“货舱”页输入相对控制器的方块偏移 `x y z`，例如 `1 0 0`，点击“添加货舱容器”；列表中的“移除”用于取消选择。偏移是结构方块坐标的差值，不是载具移动后的外部世界坐标。每轴可填 `-64` 至 `64`，最多选择 **32 个**容器。

选择的容器必须提供可读写、可安全恢复的库存接口（`IItemHandlerModifiable`），全部已选容器总槽位不能超过 **4,096**；物理化后还必须属于控制器的同一个实际结构。仅能读取、不能回滚的第三方容器不满足实际装卸条件。只有这些真实容器参加装卸，未指定的个人箱子不会自动加入。控制器登记数据不另外保存一份货物。

修改货舱清单或取消登记前，先停止任务、等运输中的运单处理完毕并清空已选货舱；运行中、有运单或仍有货物时会拒绝这些修改。货舱损坏、拆到另一结构或无法安全读取时，导航暂停并显示原因，不会把缺货订单标记为完成。

市场装货、交付和付款沿用普通帆船／马车的现有规则，失败撤销按本次装载收据恢复，不清空未选的个人库存。该接口已做真实箱子探针；完整订单流程仍待实际验收。

## 动力连接：输出面与原生控制件

先在“动力连接”页设置六个通道。点击每行方向按钮可循环选择输出面，六个通道必须齐全且各用不同的面，再点击“确认动力连接”。修改输出面后需要重新确认；配置冲突不能启用自动驾驶。

| 通道 | 默认输出面 |
| --- | --- |
| 油门 | 北 |
| 制动／停止 | 南 |
| 左转 | 西 |
| 右转 | 东 |
| 前进挡 | 上 |
| 倒挡 | 下 |

按面板北／南／西／东／上／下所对应的结构坐标面布线。控制器朝向定义导航前向，但不会把表中的北面自动改写成“车头正面”。将信号接到实际发动机、传动、舵或车轮转向／制动装置；控制器不会自行生成推力，也不会替玩家决定传动拓扑。

可以额外绑定 Simulated 的原生油门杆 `ThrottleLeverBlockEntity` 和方向盘 `SteeringWheelBlockEntity`：在相对坐标框输入对应控制件的偏移，分别点击“绑定原生油门杆”或“绑定原生方向盘”。目标必须和控制器位于同一实际结构。绑定后面板会显示偏移；“清除原生绑定”同时清除这两个目标。绑定原生控制件仍需确认六通道配置。

“油门信号：正常／反向”用于校准已绑定原生油门杆的信号方向，需依据实际传动接线选择。“限速（格／秒）”可保存 `0.1` 至 `30`；初始船舶为 `4`、陆运为 `6`。限速只是自动控制目标，实际加减速由真实动力和物理系统决定。“允许倒车／禁止倒车”控制导航是否可提出倒车指令，不能代替实际倒挡传动。

运行中不能修改端口、原生绑定、限速或终端。人工操作已绑定的原生控制件后，自动导航暂停并显示“人工接管”；准备好后明确点击“继续”。自动输出不会反复抢回玩家的控制。

## 终端、路线与运行状态

1. 将船停到码头、陆车停到驿站。进入“航行与道路”，点击“绑定附近码头或驿站”，选择的是同维度已加载、实际世界距离小于 **64 格**的最近对应终端。
2. 手持已有路线书，点击“导入手中路线书”；优先读取主手，主手不是路线书时再读取副手。选择列表中要执行的路线。
3. 确认已登记、动力已确认，有有效路线，且载具在绑定终端的停泊／等待区域内，再点击“启航／发车”。路线导入后不需要一直手持路线书；码头／市场也可通过现有调度接口分配路线。有效路线、终端和动力缺一时会提示未就绪。
4. 使用“暂停”“继续”“停止”控制当前任务。“自动返程”和“非订单自动卸货”分别切换；有订单时仍遵循订单交付与返程规则。
5. 观察状态及原因。等待地形时会停车等待近处真实数据；实际障碍阻挡时停止推进；没有前进会提示检查动力和转向；缺失订单货物不会结算为已交付。

自动驾驶保留真实尺寸、碰撞和有限前瞻加载，不把预测地图当作已经通过的航行验收。第一次带动力测试应在世界副本中分别检查船和车的前进、左右转向、停止、人工接管、继续及停靠，再进行真实订单往返验收。
