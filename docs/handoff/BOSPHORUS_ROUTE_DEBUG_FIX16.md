# fix_16：博斯普鲁斯航线与远程调试网页修复

本次只需更新服务器主模组。网络协议仍为 **22**，模组元数据版本仍为 **1.3.13**；现有协议 22 客户端无需更新，服务器现有 MarketWeb fix_15 可以继续使用。

## 航线失败原因与修复

用户日志中的**君士坦丁堡与塞瓦斯托波尔之间航线**在 `cell=16` 扩展 **683091** 个节点后返回 `NO_WATER_PATH`，并非节点预算耗尽。官方遮罩的反向复现精确命中这个计数。16 格网格只使用格中心，博斯普鲁斯的窄水道可能没有任何中心落入，导致真实相通的水域在该网格上被判为不连通。

使用官方 **Tellus Land Polygons v1.0.0** 重现了相同问题。测试文件 SHA-256：

```text
ab142dc692ee9607eeb23802219c25f7dff5340cfe3cc8d7ee2083acfac3afa2
```

修复保留原有 **16–128 格初始网格**；不通时继续尝试 **8 → 4 → 2 → 1 格**。每次细网格最多扩展 **65536** 个节点，四次合计最多 **262144** 个额外扩展节点。此上限只计算细网格搜索扩展，概览距离场和航段分类仍有额外工作。官方遮罩在 1:300 比例下需要细化至 2 格，单独增加 8 格重试不足以覆盖该情况。

- 直航段增加逐格精确覆盖检查：检查线段经过和接触的格子及其 **2×2 船体占地**，避免跳过单格陆地；仍保留离岸余量检查。
- 普通扩展和双向前沿拼接使用相同角点规则，防止拼接阶段绕过两侧陆地限制。
- 缺失地形返回 `TERRAIN_NOT_READY`，不会缓存成陆地或当作已知水域。
- 取样缓存满时在新取样插入前淘汰，避免先扩容再清空造成的瞬时内存峰值；命中仍复用原缓存。

## 远程调试网页

服务器内执行：

```text
/sailboat routedebug start 8899 public
```

该命令监听 `0.0.0.0:8899`，可通过面板 TCP 转发访问。命令输出本次启动的完整访问链接；将其中的 `127.0.0.1:8899` 换成用户当前的外网映射，保留完整令牌：

```text
http://zjc.rainplay.cn:54587/?token=<本次令牌>
```

`<本次令牌>` 必须替换成命令实际输出的值。以下命令可以重新查看当前链接或停止服务：

```text
/sailboat routedebug status
/sailboat routedebug stop
```

所有公网模式接口都需要令牌。浏览器打开完整链接后会获得 HttpOnly、SameSite=Strict 会话 Cookie，页面后续请求可正常访问；响应禁止缓存和传递来源链接。令牌反馈不向其他管理员广播，HTTP 日志不记录令牌查询串。重新启动服务会生成新令牌，旧链接及旧 Cookie 随之失效；完成调试后执行 `stop`。

原有本机模式保留：`/sailboat routedebug start` 默认监听 `127.0.0.1:8899`；`start <port>` 仍是本机模式。

NBT 页面现在直接调用正式生产求解流程，包含泊位验证及最终检查；只计算和展示，不注册、导入或保存航线。预览在工作线程生成，最长边不超过 **1024 像素**，包含完整路线和绕行部分；使用内置全球概览作定位示意，不为出图逐点强制加载或生成区块。底图不能代替真实方块或船宽校验结果。

**HYBRID / NOISE 仍是旧诊断流程，可能强制加载或生成区块。上述 NBT 的不强制加载说明不适用于它们。**

## 安装

1. 停止服务器。
2. 将旧 SailboatMod **主模组 JAR** 移到 `mods` 目录之外备份，保留现有世界存档备份。
3. 将本次 `sailboatmod-1.3.13-fix_16-neoforge-1.21.1.jar` 放入服务器 `mods`；确认目录中只有一个 SailboatMod 主模组版本。
4. 保留现有 MarketWeb fix_15、GeckoLib、LDLib2 及其他兼容依赖，不重复放入同一依赖的不同版本。
5. 启动服务器，重新创建或计算相关航线；需要外网调试时再执行上述 `public` 命令。

玩家客户端无需为本次服务器修复更换 JAR。需要回退时，停服后恢复备份的旧主模组 JAR，并移出 fix_16，避免同时加载两个版本。
