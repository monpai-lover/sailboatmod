# 空运兼容第一版：接入与验收

本次代码位于 `codex/air-transport`，基于 NeoForge 1.21.1 分支。采用玩家自建机场、登记设施的建设方式。当前提供物理空运接入及网页展示；远处离线推进尚未接通，不能作为已经可用的功能发布。三类飞机的真实起降、货运及重启情形仍需在装有依赖的 Minecraft 世界中验证。

下一阶段的三机型强化、机场继续建设、海陆驾驶与共用货物/设施规则见 [物理物流设计入口](../physical-logistics/README.md)。该阶段目前只有设计和实施准备，不能用其中的目标能力替代本页的当前运行边界。

专用服务端的 Sable 客户端重载反射问题已在源码修复，当前构建为 fix_15。见 [修复与版本兼容说明](../SABLE_DEDICATED_SERVER_REFLECTION_FIX.md)：用户原 fix_12 热补丁仍是协议15，当前分支是协议17，不能跨协议混用。

附属模组按可选安装和复用处理，见[安装清单与接入边界](../physical-logistics/optional-addons.md)。FC 已有真实终端适配；AL、Automatics 等独立玩法不会仅因安装自动成为 Sailboat 订单或网页任务。同一载具只启用一个自动控制后端，当前尚未实现所有第三方控制者的统一互斥。

## 已接入的路径

- `飞行器登记控制器` 登记航空学/Sable 结构、现有货舱与稳定载具 UUID，选择飞艇、旋翼或固定翼。通过同结构的真实 Create Flight Control 导航终端执行三维航线。
- `机场登记台` 接入城镇运输网络及仓库。跑道、停机坪和飞艇泊位是现有玩家建筑的坐标登记，不生成建筑。
- 市场自动派发、自提及返航沿用已有货物清单、订单与到账机制。落地必须满足整个机身进入登记设施、速度不超过 0.25 m/s、机身底部与停机平面高度差不超过 0.5 格及当前净空复验。
- 网页地图增加三种航空图标与筛选、世界高度 Y、飞行阶段、执行方式、机场与设施几何。机场目录可公开浏览；物流详情继续使用原有身份和可见性规则。
- 飞行任务日志记录身份、阶段和表示形式；只有有实际存放凭证的离线任务才允许免于孤立订单清理，普通物理飞机没有宽泛豁免。

## 依赖与控制权

本次核对的接口版本为 Create Flight Control 0.8.3、Sable 2.0.6、Automated Logistics 0.7.0。物理飞行使用航空学、Sable、Create、Flight Control 及它们各自声明的依赖；AL 并非当前物理空运的必需依赖。Sailboat 没有打包这些模组的代码或资源。Create: Simulated 不再是识别 Sable 结构的硬前提。

飞艇和旋翼的 FCC 使用 `GENERAL`，固定翼使用 `FIXED_WING`。先把飞机、控制器与执行器调到可以由 FC 正常飞行，再接物流。Sailboat 不替代真实发动机，不直接施力，也不自动改写飞控增益。硬件不匹配、失效的双向链接、过期状态、卡片变更或外部红石启用冲突均会留下诊断。

导航终端须已经插入真实航线卡。Sailboat 在停稳并通过起飞检查后更新该卡，等待 FC 完成校验，再启用终端。不要把其他系统正在使用的终端同时分配给物流。

## 建设与登记

1. 在两端城镇中建造机场。市场继续绑定城镇仓库；机场是同城镇的航空运输终端。
2. 放置 `sailboatmod:airport`，由有机场所有权及城镇管理权限的玩家命名。
3. 建好支撑面、跑道/停机坪/泊位，并清理净空，再登记设施。
4. 创建单向机场航线；需要独立反向派发时，在另一端也登记航线。
5. 在飞机上放置 `sailboatmod:air_vehicle_registration_controller`，登记现有货舱，在动力页选择机型并填写导航终端相对登记器的方块坐标偏移。
6. 飞机完整停在匹配设施内，选机场航线后启动，或交由市场自动派发。

命令格式：

```text
/airport help
/airport <登记台 x y z> name <名称>
/airport <登记台 x y z> register <设施id> <runway|helipad|mooring> <起点 x y z> <终点 x y z> <宽度> <净空高>
/airport <登记台 x y z> list
/airport <登记台 x y z> validate <设施id>
/airport <登记台 x y z> remove <设施id>
/airport <登记台 x y z> route <目标登记台 x y z> <巡航Y>
```

端点 Y 是支撑面上方的空气格，即预期机身底部高度。宽度 5–32 格、净空高 4–64 格，跑道水平且长 32–512 格，其他设施端点距离不超过 32 格。设施距登记台最多 512 格，每机场最多 16 处。整片设施及两端进近范围必须属于机场所在的同一受管辖城镇；跑道两端额外检查 16–64 格的斜向进近净空。

固定翼要求跑道，旋翼允许停机坪或跑道，飞艇要求泊位。起飞时选择飞机实际停放的设施，目的设施按机型匹配、占用及净空检查选择。未知或未加载区块不算通过；`WAITING` 表示分段扫描尚未完成。预约保留同一载具 UUID，防止每次重试都从头开始。

设施宽度检查采用飞控逻辑原点至机身包围盒各角最大水平距离的两倍，再加 2 格余量，避免原点偏心或落地朝向变化导致机身超出设施。机身很长的固定翼可能被保守拒绝，需要更宽的设施。给固定翼预留足够长的滑跑空间，当前要求跑道至少为规划巡航速度乘以 6 秒、且不短于 32 格；这只是初步规划门槛，不是针对机型验证过的起降性能模型。界面的“规划巡航速度”不会限制实际 FC 速度，必须根据飞机真实速度及制动能力调校硬件和建设跑道。

## 检测与性能边界

设施扫描每个机场每游戏 tick 最多执行 2048 步，按旋转走廊内实际方块计算容量。真实 Minecraft 类库探针中，120 格长、16 格宽、16 格净空的轴向跑道由 137 次扫描调用降到 76 次；同长斜跑道为 79 次，不再因外接矩形过大而误拒绝。

一般验证缓存为 20 tick。起飞使用独立请求 UUID 的准备快照：每端在同一轮中只扫描一次，预约直接消费快照，解决长短跑道完成时间错开而永远不能同时通过的问题。每次仍实时复核已加载区块、真实机身位置与占用。每轮最迟 7010 tick（约 350.5 秒）过期，该上界来自最大合法扫描步数、5 tick 重试间隔及两端的最坏串行耗时；普通设施更快。这是有界准备期间的扫描快照，不是起飞瞬间对全机场的原子检查。不要在准备过程中改造跑道，改造后应取消并重新开始预检。

飞行中的扫掠探测也有预算，会显示障碍/未知地形诊断，但目前没有经实飞验证的自动绕障或自动调参能力。检测到未知地形不能被当作清空，也不会因为离玩家远而直接关掉固定翼动力。

物理飞机维持现有区块加载窗口。网页只展示服务端已提供的状态，不用动画插值推导实际到达，不把缺失高度填成 0。

## 尚未完成的部分

**离线推进：** 当前运行时保持 `PHYSICAL`，显示 `sable_custody_transaction_missing`。任务日志中的虚拟航程状态机只是基础代码，没有接入存放后端。Sable 的公开接口不足以提供持久独占存放、物理移除确认、明确 IO 成败及幂等恢复；AL 的现有恢复路径会清零速度，不适合固定翼空中接管。需要补丁及崩溃/重复恢复/燃料扣减测试后才能启用。详见 [存放事务与最小补丁契约](../../../src/main/java/com/monpai/sailboatmod/compat/automatedlogistics/API_EVIDENCE.md)。

**中途重启：** FC 0.8.3 不保存航段执行进度；直接接纳新任务 UUID 会从整张卡的首段重放。恢复逻辑在加载时及初始化期间每 tick 核对同结构和真实卡片指纹，能确认归属后取消旧卡的自动执行，保留货物与任务记录。中途任务需要人工接管，降落原出发机场后点继续重新预检，或降落目标机场后点继续核验交货。不能宣称无缝重启续航。若 Sable 身份尚未初始化，系统不能操作未经确认的终端，也尚不能保证 FC 在其他方块实体先 tick 时绝无短暂自启；需要真实服务器验证加载顺序，必要时增加 FC 恢复钩子。固定翼空中恢复仍属未完成验收项。

**真实游戏验收：** 尚未进行。应在独立测试世界依次验证三类飞机的起飞、巡航、完整落地、货物到账、自动自提与返航，再检查等待中的扫描、占用跑道、未知区块、外部红石争用、换卡、拆除控制器和服务器重启。核对每次货物数量、订单状态、实体 UUID 与控制权均保持一致。自动化测试通过不能替代这些实飞结果。
