# fix_18：真实地形接点、水面高度与调试网页长任务

仅更新服务器主模组。游戏网络协议保持 **22**，模组元数据版本保持 **1.3.13**；玩家客户端、现有 MarketWeb 附属及依赖均不需要更新。

## 两份日志对应的问题

第一份日志的全局导向已成功，但 `(32332,65,-50204) → (32340,65,-50212)` 的精寻在步长 8、4、2、1 都出现 `startSnap=null`，扩展节点为零。旧逻辑直接接入遮罩允许的中间点，没有先核对接点的真实地形；接点实际不可航时，下一段从无效位置起搜。

第二份日志已出现“成功 扩展43526节点 航点276个”，随后在 HTTP `sendResponseHeaders` 出现 `stream is closed`。这是计算成功后的连接写出失败。日志本身不能确定是浏览器、代理还是网络中断；长时间维持同一个 HTTP 请求使这类断连影响结果交付。

## 航线修复

- 在接入直航段前验证正式起点和每个中间接点的真实 2×2 船体通行条件。地形尚未准备好则等待；正式起终泊位的位置和高度不改动。
- 无效或高度不一致的内部导向点不再作为精寻起点，改用真实地形局部绕行；长距离已认证直航段尽量保留，局部修复两端尾段。
- 共线压缩保留直航／精寻边界。整数共线裁切保持原认证几何；四舍五入改变几何时必须重新经过原生遮罩认证，未完成或超时的认证不能放行。
- 修复 Tellus 远洋预测水面低一格的问题：Tellus 普通海面最高水方块为 Y=64，船体位置为 Y=65；远洋预测器现在使用已验证起点的船体高度，与近港真实 NBT 水面一致。

## 调试网页

网页现在先提交后台任务并立即获得任务编号，再每秒查询状态。临时断线或代理 504 会继续查询原任务，不会重新计算；提供取消按钮，并保留最终失败原因和诊断日志。旧同步接口继续兼容，长航线请刷新页面使用新的异步流程。

```text
POST /api/route/start?a=0&b=1&mode=tellus
GET  /api/route/jobs/{jobId}
POST /api/route/jobs/{jobId}/cancel
```

以上接口均沿用原令牌／会话鉴权。单个工作线程、最多两个排队任务、最多四条任务记录；任务自提交起最多 600 秒，完成结果最多保留十分钟，记录满时允许淘汰较早的已完成记录。停服会取消任务并关闭服务。真正的求解和图片编码异常仍会报告错误，单独的响应写出断连不再误报为求解失败。

启动命令不变：

```text
/sailboat routedebug start 8899 public
/sailboat routedebug status
/sailboat routedebug stop
```

使用命令输出的完整令牌链接；通过端口映射访问时只替换地址和端口，保留 `?token=...`。更新后刷新网页。

## 安装

停服，将旧 SailboatMod 主 JAR 移出 `mods` 备份，放入压缩包 `server-mods` 中的 fix_18 主 JAR。不要同时保留两个主 JAR；保留现有 MarketWeb、GeckoLib、LDLib2、其他依赖和存档。玩家客户端不需要替换。

主 JAR：`sailboatmod-1.3.13-fix_18-neoforge-1.21.1.jar`，**27845076 bytes**。

```text
SHA-256 908f2a3016e149064aa2bd1dc3c924cf0ba919bc9a20ddc1155eaf4420e510e9
```

压缩包内 `verification/` 保留分轮测试计数、构建日志、兼容性比较和独立服务器检查结果；`SHA256SUMS.txt` 可核对全部交付文件。
