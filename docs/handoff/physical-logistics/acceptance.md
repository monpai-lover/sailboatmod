# 物理方块载具物流验收矩阵

状态：2026-10-30 的待执行验收设计；不是当前测试报告。对应 [总体设计](../../superpowers/specs/2026-10-30-physical-logistics-design.md) 与 [M0a 计划](../../superpowers/plans/2026-10-30-physical-logistics-safety-contracts.md)。所有未填写结果均表示尚未执行。

## 1. 验证层次

| 层次 | 能证明什么 | 不能证明什么 |
|---|---|---|
| L1 纯模型/服务测试 | 状态迁移、边界计算、模拟事务回调、重复/乱序行为 | 真实 API、制动力、货舱存盘、游戏帧表现 |
| L2 真实模组适配探针 | 所锁定版本的坐标/单位/返回值、同结构约束、控制交接 | 任意玩家构造的载具均可稳定运行 |
| L3 独立 Minecraft 场景 | 指定机体/船/车的实际物理驾驶、设施、库存、付款与重启行为 | 任意模组组合的兼容、任意突发事件都能自动避险 |
| L4 网页与多人 | 真实 API 权限、新鲜度、重连状态、界面显示与游戏一致 | mock 中的飞行动画能证明服务端实际完成运输 |

M0a 只属于 L1，不应因此开放新精确停靠、避障或自动校准功能。一次异常恢复的正确结果可以是隔离并要求核对，不能为了得到绿色结果把未知状态强行改成成功。

## 2. 固定测试资产和证据

使用可删除的独立世界或用户世界副本。保存原始基线，不在生产世界进行碰撞、拆货舱、强制退出或重复恢复测试。为每份世界记录依赖 JAR 文件名、版本和 SHA-256；FC 0.8.3 / Sable 2.0.6 / Aeronautics 与 Simulated 的具体组合分别标注，不能用一个版本的结果替另一个版本背书。

固定五个样机：飞艇 A、旋翼 R、固定翼 F、水面船 W、单体 Offroad 车 L。每个保存结构/执行器配置、朝向和局部锚点、性能档案版本、货舱位置、动力与燃料接线、空载/中载/批准满载配载。登记器零质量、结构总质量正值独立核验；没有真实物品质量模型时只称货物配载级别，不标成实测增重。

建立双机场、双港口、双驿站和一个中转仓。机场包括一个跑道占用冲突、独立旋翼坪、飞艇泊位；港口包括低桥、浅滩和窄航道；道路包括平地、90 度转弯、坡道、窄桥、断桥和带退出空间的装卸位。未完成实际滑行能力时，固定翼使用跑道末端装卸并保持跑道占用。

每次记录：

```text
runId, gitSha, buildSha256, dependencySet, worldCopy, scenarioId
missionId, legId, carrierRef, physicalGroupIds, generation
profileRevision, routeRevision, facilityKey, geometryRevision, leaseToken
serverTick, observationTick, movementPhase, orderStatus, representation, controlOwner
worldPose, linearVelocity, angularVelocity, bounds, scanCoverage, scanAge
cargoTransferId, manifestLineId, sourceQuantity, vehicleQuantity, targetQuantity
escrowState, paymentReceiptId, reasonCode, recoveryAction
```

向量与速度标注单位；没有来源的值写 null。货物指纹包含 item ID、组件和数量，不能只比较物品名字。收入、退款及托管余额单独核对，不能只看页面“已送达”。每个失败保存服务端日志和关键前后 NBT/收据；真机录像或截图必须来自对应 runId。

建议结果目录为 gitignored `build/physical-logistics-validation/<runId>/`；可公开的简短结论、依赖清单及截图再放到本 handoff 目录。世界、第三方模组、令牌和完整玩家隐私数据不入 Git。

## 3. 共用安全与货物合同

| ID | 场景/故障切点 | 要求的结果 | 层次/阶段 |
|---|---|---|---|
| C01 | 关闭可选模组、错误执行器、跨结构货舱 | 主模组可启动；对应能力不可用，禁新自动派发 | L1/L2，M0b |
| C02 | 两登记器同结构、重组、控制器与货舱分裂 | 业务 UUID 不复制；冲突隔离，重新绑定前禁控制/装卸 | L1/L3，M0b |
| C03 | 3D 速度不低、原地旋转、只一角入位、无支承 | 停泊证据不成立，绝不推进交付 | L1/L3，M0a/M0b |
| C04 | 重放/乱序/过期观测、几何或任务代次改变 | 稳定窗口失效，旧许可不能用到新任务 | L1，M0a/M0b |
| C05 | 玩家接管、外部红石开关、旧 FC 确认/旧网页命令 | 原生玩家控制优先，旧命令不能夺回控制；货物不动 | L1/L2/L3，M0b |
| C06 | 装货容量模拟后，货舱更换/插入部分成功/启动失败 | 只回退本次明确插入的货物，不清个人库存，不二次扣源库存 | L1/L3，M0c |
| C07 | 目标仓满、只收部分、短货、错误物品组件 | 确认实际数量；剩余保留原货权；短货不按完整订单结算 | L1/L3，M0c |
| C08 | 同一 manifest 行/transferId 两次交付，CLAIMED/DELIVERED 重放 | 返回原收据，不再插入、不再次支付 | L1/L3，M0c |
| C09 | 退款与未决卸货交错 | 不能同时退钱、恢复挂单库存、又让收货方得到货；未确认归属则隔离 | L1/L3，M0c |
| C10 | 在 PREPARED、取出、插入、COMMITTED、付款前后分别终止并重启 | 按实际参与者证据恢复；任意 IItemHandler 不能证明时进入 RECONCILE_REQUIRED，不自动回放 | L1故障注入 + L3，M0c |
| C11 | 旧租约释放/续租、同载具新航次、过期但实体仍占用 | token/代次校验；保留真实占用，不能超时放行重叠交通 | L1/L3，M0c |
| C12 | 停稳后移动车体、拆货舱、改变姿态 | 同业务 tick 阻止下一批传货；已提交批次仍保留确认记录 | L1/L3，M0c |
| C13 | 故障仍有速度、未知区块/身份暂不可读 | 保留必要运动区加载与占用；无证据不销毁、不交付 | L1/L3，M1 |
| C14 | 普通巡航经过点、终端停止点和让行线 | 经过点可不停车，停止点必须满足对应门禁 | L1/L3，M3/M4 |
| C15 | 返程、单向路段、原路不可反向进入的泊位 | 重新生成合法离场/回程程序，不简单反转航点 | L1/L3，M2/M3/M4 |

## 4. 检测与调度性能

| ID | 负载或变化 | 必须测量/断言 |
|---|---|---|
| P01 | 扫描体积超过单次预算，机体每 tick 移动 | 新旧重叠证据复用，最终覆盖有进展；不能持续只扫前缀 |
| P02 | 轴向/斜向长机体、转弯时尾部扫掠 | 不漏尾部/旋转体积；保守拒绝与真实障碍区分 |
| P03 | 已扫区域改方块、流体变化、未登记物理结构进入 | 相关证据失效或动态风险被检测；未支持结构查询明确 UNKNOWN |
| P04 | 多机场、多载具同时请求扫描 | 全局操作数与耗时上限生效；记录最大等待年龄，不允许无界饥饿 |
| P05 | 加载延迟、视距变化、达到128区块/全局请求上限 | 根据可验证前瞻限制新准入；不为了新任务撤掉运动中载具关键票据 |
| P06 | 1/10/30个批准样机并行，分别空载/满载 | 记录本模块耗时、Sable物理耗时、MSPT、票据数、GC、吞吐量；报告硬件和完整配置 |
| P07 | 网页断网/慢客户端/SSE重连 | 游戏 tick 不等待 HTTP 写出；队列有界；重连刷新权限与版本 |

预算候选为全局每 tick 8192 检测操作且最多 2 ms 工作时间，单任务每次 2048。先跑基准，再决定上线值；如果机械结构自身物理成本超标，明确归因，不把网页降采样称作物理优化成功。

## 5. 三类空运

| ID | 场景 | 通过条件 |
|---|---|---|
| A01 | 各类空载/中载/批准满载起飞、运输、停稳、装卸、返航 | 正确程序与真实动力；货物/费用/身份守恒，返程重预检 |
| A02 | 固定翼朝向反向、起飞位置太靠后、剩余跑道不足 | 起飞前拒绝并给出具体原因，不只比较跑道总长度 |
| A03 | 固定翼稳定进近门失败、跑道被占、复飞出口不净空 | 仅在已验证连续控制能力存在时复飞/备降；否则提前拒绝这类自动任务并报告限制 |
| A04 | 飞艇惯性漂移、旋翼下沉、原地转动 | 停泊不成立；不能仅凭线性低速或到点交货 |
| A05 | 偏心逻辑原点、重新序列化锚点、超宽/超高机体 | 世界姿态一致，机体完整入区；旧原点偏移不能复用 |
| A06 | 两机争跑道、第三个未登记结构进入进近区域 | 预约/实际占用独立；不能只因登记表没有该物体就放行 |
| A07 | 航行中想改路线但原生 API 必须 CANCEL | 不执行会释放控制的自动换卡；维持已批准路线并显示能力限制 |
| A08 | 换卡、FCC断链、启用信号争用、拆登记器 | 不伪造原生确认，明确控制权；固定翼不被通用“暂停”挂在空中 |
| A09 | 起飞/巡航/进近重启，故意改变方块加载次序 | 无旧卡偷偷重放；未有原生fence补丁时记录未通过，无缝续航保持关闭 |
| A10 | 落在同机场另一兼容坪位 | 先显式核验并改派设施，再出具交货许可；原分配租约正确处理 |

固定翼滑行不是本机型默认拥有的能力；无原生刹车/转向证明时测试玩家预停到跑道起飞位、跑道末端停稳装卸的受限流程。独立货运停机位需要另跑实际滑行测试。

## 6. 海运与陆运

| ID | 场景 | 通过条件 |
|---|---|---|
| W01 | 满载吃水、浅滩、桥下通道、上层建筑碰桥 | 水深与水面上净空分别验证；起终泊位不享有免检 |
| W02 | 大船转弯、船首已入区但船尾在外 | 扫掠/完整停靠包络生效，不提前交货 |
| W03 | 油门有但刹车口空接、低速舵失效、无倒车 | 能力声明不足拒绝相关路线；不把信号写成功当停船成功 |
| W04 | 靠泊横漂/偏航、装卸后浮态变化 | 持续复核；实际保持失效时停下一批传货，离泊重测性能 |
| W05 | 两船对向进入窄航道、港池无退出空间 | 互斥与出口许可生效；等待区退让，无传送/穿模 |
| W06 | 无锚的动力保持、耗尽保持能源 | 显示动力保持与消耗，不能称已抛锚并关闭加载 |
| L01 | 连续道路航点、90度弯、长车内轮差、窄路 | 经过点不强制停车；不可行弯道出发前拒绝 |
| L02 | 断桥、仅中心线连通、车轮悬空、低隧道 | 车体净空与轮胎支承分别校验，不能沿预测路段直接驶入 |
| L03 | 上下坡、横坡、湿滑制动 | 使用保守减速度和坡度档案，稳定驻车后才能交货 |
| L04 | 高速时目标在后、倒车后有障碍、反复前后换挡 | 先刹停/空挡/确认再反向；后方与倒车范围受限 |
| L05 | 路口出口堵塞、窄桥对向、TTL到期车未驶出 | 不抢进路口；实体占用一直有效；队列不无限饥饿 |
| L06 | 转向/刹车断开、玩家上车接管、重启 | 禁止旧自动输出夺控，任务/货物保留；故障停稳前保留加载 |

原生帆船与马车需单独跑兼容回归；M3/M4 新模式门禁不能改变旧实体驾驶器的正常路径。两栖、铰接、多体、乘客和流体不列入首批通过范围。

## 7. 远处虚拟推进的独立门槛

| ID | 故障 | 正确结果 |
|---|---|---|
| V01 | 托管存盘失败、部分结构组移除、IO异常被上游吞掉 | 不出具独占托管收据、不推进虚拟距离；进入明确核对状态 |
| V02 | 每个托管/移除/恢复边界重启；同时原生加载/其他materializer | 同一结构组至多一个权威表示；重复请求返回相同结果或隔离 |
| V03 | 燃料扣减重复、未知发动机、超预算距离 | 不免费移动、不重复扣；未知燃料组合拒绝虚拟模式 |
| V04 | 玩家高速靠近、传送到目的位置、维度转入 | 跟踪/交互fence成立后才开放组合；没有该能力则该场景禁虚拟 |
| V05 | 固定翼恢复速度/姿态/原点变化、恢复区域被挡 | 第一物理步前正确恢复动量与控制；无法证明则不物化、不伪造到达 |
| V06 | 服务器关闭数小时后启动 | 不用墙钟补跑；按已提交模拟时间与货物记录恢复 |

## 8. 网页与权限

- 在真实运行时对照物理位置、世界Y、线速度、阶段、控制方、租约和装卸数量；浏览器动画不会推进订单。
- 对 PHYSICAL_OBSERVATION / VIRTUAL_AUTHORIZED / LAST_KNOWN、未知高度/燃料/质量、等待/核对状态分别截图。
- 测试托运人、现有同国权限用户、无权限用户和切账号后的 SSE 重连；买家是否能看私人轨迹沿用明确授权规则，不能随新字段扩大可见性。
- 公共机场几何不意味着预约和私人载具详情都可公开。离线终端显示登记资料与“可用性未核验”。
- 重复点击继续/取消、旧generation、租约已变、另一玩家已接管时，界面显示服务端实际结果。
- 浅色/深色、长名称、中文原因、空数据、慢接口和重连均检查。mock与实服截图分开目录并标注。

## 9. 交付通过标准

五种样机 × 三档载荷 × 每档 10 个单向载货航段 = 150 趟；其空载返程另行记录，不混入载货样本。指定场景全部无误交付、货物复制/丢失、重复付款、无许可控制争用；异常场景按矩阵拒绝/隔离也可通过，但必须保留原因和恢复步骤。

游戏保存重启与进程崩溃/IO失败分别报告。不能把正常退出后成功恢复当作断电事务已经证明。新模式最终需全套 Java/前端回归、`releaseMod`、实际 JAR 启动、真实样机运行与网页截图；检查内嵌库和8120个Minecraft网页资源是否仍完整，不因源码测试成功跳过包内容检查。

结果表使用 `PASS / FAIL / NOT_RUN / UNSUPPORTED`，每个 PASS 附 runId；UNSUPPORTED 必须对应明确的能力关闭，不能计入已完成真实自动运输。工程文档、纯模型、编译、API探针、真机运行和发布状态分别写，不混为“全部验证通过”。
